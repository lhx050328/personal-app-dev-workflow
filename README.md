# personal-app-dev-workflow

**个人应用/软件/工具/网页的全生命周期开发工作流技能包** —— 让 AI 从"帮你做一个应用"升级为"陪你走完一个产品的完整生命周期"：调一次技能、全程不忘流程；做完还能持续迭代、随时回退，就像市场上的真实产品一样。

> 这是一个 Skill（技能包）：给支持 Skill 机制的 Agent 平台（如豆包工作等）使用。放进技能目录即可被 AI 调用。

## 解决什么痛点

用 AI 做过开发的人都会遇到这几件烦心事：

1. **技能只在第一次调用被记住，对话一长 AI 就忘了流程**——尤其对话被自动压缩后，早期约定全丢；
2. **交付完就是一次性**——加个新功能要重新从头讲需求，项目没有"版本"概念；
3. **设计前拍脑袋**——不查同类产品、不搜现成方案就动手，容易造重复的轮子；
4. **改坏了没法回退**——没有版本留痕，出问题只能干瞪眼；
5. **Windows 下 git 写操作被 agent 通道拦截**——E 盘等目录 add/commit 报 Permission denied，项目卡死。

本技能包把上述问题全部制度化：**每次开发都按"需求→边界→技术(先调研)→实现→验证→维护"七阶段走，每步等你确认；每个版本入库可回看可回退；对话被压缩后靠项目档案无损恢复。**

## 核心特点

- **调一次、全程不忘**：项目 AGENTS 运行内核每轮自动注入 + 档案四件套落盘，长对话/新对话都能恢复进度，不从零重来；
- **七阶段确认闸门**：每个阶段结束 AI 停下来等你"确认"，风险前置、成本可控；
- **设计前必调研**：阶段1查竞品、阶段3强制检索开源实现与最佳实践，来源入档，不凭空造轮子；
- **变更双通道 + 语义化版本**：bug 走补丁快通道（1.0.0→1.0.1），新功能走完整循环（→1.1.0），AI 自动编号，用户无需记规则；
- **三档自然语言回退**：说大白话"退回上个能用的版本"即可回退，**回退不删历史**，问题版保留可追溯；
- **抗上下文压缩三锚点**：AGENTS 每轮注入（压不掉）+ 磁盘文件可重读 + 你一句话复位；
- **Windows git 双通道（egit）**：官方 git 被拦自动切纯 Python Dulwich 后端，E 盘项目不再卡死。

## 快速开始

1. 把本文件夹放入平台的技能目录（如 `.user_skills/`、`skills/`），重启识别；
2. 新建项目对话，说一句："我想做一个 XXX 应用/工具/网页"；
3. 然后你只需要：**回答 AI 的具体场景问题 → 说"确认" → 试用后反馈**。

### 示例对话

```
你：我想做一个本地 TXT 阅读器，能记住阅读进度。
AI：好的，我们来做一个阅读器。
    【阶段0：项目初始化】
    - 项目名我建议叫 mark-reader，可以吗？
    - 项目结构、AGENTS.md、git 仓库会这样建…
    确认没问题的话我就开始初始化。
```

之后每个阶段结束 AI 都会停下等你确认，全程不需要你记任何命令或版本号。

### 支持的全部场景（触发词）

- 做新应用："我想做一个 XXX"
- 继续做 / 接着上次："继续"（同对话或新对话都行，AI 会先输出恢复摘要）
- 迭代加功能："帮我加个书签功能"
- 修 bug："打开大文件很卡"
- 回退版本："退回上个能用的版本 / 撤销刚才的改动 / 只把某块改回去"
- 接入旧项目："这是我以前的项目文件夹，想接着做"

## 项目结构

```
personal-app-dev-workflow/
├── SKILL.md                    # 技能核心（薄内核约90行：元规则/流程图/双通道/规范）
├── references/
│   └── workflow-detail.md      # 七阶段完整操作规范 + 抗压缩专题A + 回退专题B + egit 附录
└── assets/
    ├── AGENTS.md.template      # 项目约束+运行内核模板（阶段0 生成项目 AGENTS.md）
    ├── PROJECT-STATE.md.template  # 项目状态索引（≤40行，每轮读写）
    ├── BACKLOG.md.template     # 需求池（MoSCoW 优先级）
    ├── CHANGELOG.md.template   # 版本日志（SemVer + Keep a Changelog）
    ├── DECISIONS.md.template   # 决策记录（ADR 五段式）
    ├── product-design-doc.template # 产品设计文档模板
    ├── tech-design-doc.template    # 技术方案文档模板
    └── egit.py                 # Windows git 双通道工具（可选）
```

## 适用场景

- **个人开发者 / 学生**：用 AI 做小工具、网页应用、学习项目，想要"像商业产品一样"的开发流程；
- **重度 AI 开发用户**：受够了"AI 做完就忘、对话一长就断片"，需要长期项目持续迭代；
- **Windows 用户**：遇到 git 在 E 盘被拦截、需要可靠版本管理兜底。

## 平台差异说明

- **豆包工作等（有 AGENTS 每轮注入机制）**：抗压缩效果最强（系统每轮自动喂运行内核）；
- **Dify 等（无注入机制）**：靠落盘 + 提示词强约束 + 用户一句话复位兜底，效果弱一档但不会断片；
- **只收单个 md 的平台**：可自行把 SKILL.md + workflow-detail.md + 模板合并为单文件导入。
